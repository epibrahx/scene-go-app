## 一、产品本质

### 一句话

SceneGo 帮出境旅行者在语言不通时，**秒级生成一张当地人能秒懂的大字卡片**，递出手机完成沟通。

### 与翻译 App 的根本差异

| | 翻译 App | SceneGo |
|---|---|---|
| 给谁看 | 用户自己 | 用户对面的当地人 |
| 字号 | 正常阅读 | 尽可能大，3 米外能看清 |
| 语气 | 中性直译 | 符合当地文化的礼貌表达 |
| 上下文 | 无 | 场景化（出租车/餐厅/药店/海关） |
| 附加信息 | 无 | 当地惯例提示（出租车必须打表是法律规定） |
| 终态 | 用户读完关掉 | 用户把手机递出去 |

**SceneGo 不是翻译器。是一份给当地人看的、格式化的沟通文档。**

## 二、用户何时打开 SceneGo

不是闲着无聊刷一刷。是这些时刻：

1. **出租车上**——司机没打表，你需要现在、立刻表达「请打表」
2. **餐厅里**——菜单全是泰文，服务员站在旁边等你点
3. **药店柜台前**——头疼到炸裂，你不知道「布洛芬」泰语怎么说
4. **迷路**——大晚上在陌生巷子里
5. **被骗了 / 出事了**——恐慌，需要求助

共同特征：**紧张、时间紧迫、认知负荷已满、手可能在抖。**

## 三、用户三种状态

| 状态 | 情绪 | 需要 | 首页对他的价值 |
|---|---|---|---|
| **「我现在就需要」** | 紧张、急躁 | 最快速度出卡 | 别挡路 |
| **「我待会可能需要」** | 从容、有准备 | 浏览、探索、提前准备 | 给我灵感 |
| **「我就看看」** | 好奇、评估 | 三秒内理解 App 能做什么 | 展示能力 |

首页的默认视觉焦点服务「紧急」，但容器里装着「准备」和「探索」的内容。

---

## 四、首页设计原则（暂定）

1. **一眼就知道干什么** — 不靠文字解释，靠一个真实的卡片示例
2. **一步就能开始** — 说话/打字/拍照，三种入口触手可及
3. **一秒都不浪费** — 成卡后直接全屏展示，无额外跳转

## 五、值得探索的首页方向

以下六种形态在发散阶段被讨论过。**不是方案**，是方向性思路，供下一轮设计参考。

### ① 空气模式
打开 App = 已经在听。说中文自动出当地语言大字。像手电筒——打开就亮。
- 优：零操作到出卡
- 忧：隐私、噪音误触、用户可能还没想好说什么

### ② 指南针模式
首页不是功能入口，是情境仪表盘。国旗+城市+当地时间+快速须知+紧急电话。
- 优：还没操作就已经在帮你
- 忧：信息量大，紧急时反而慢

### ③ 口袋翻译员
首页是对话界面（类 iMessage），输入「帮我跟司机说打表」，回复是一张内嵌卡片。
- 优：对话是最自然的心智模型
- 忧：核心需求是单向表达，不是来回聊天

### ④ 街景感知
首页就是相机常开取景器。对着菜单/路牌自动识别。
- 优：拍照场景零操作
- 忧：不是每次都需要拍照

### ⑤ 任务流
首页问「你需要做什么？」——跟人沟通 / 看懂东西 / 紧急求助，三个大选项。
- 优：把用户从「创造者」变成「选择者」，降低认知负荷
- 忧：多一步选择

### ⑥ 情绪锚点
首页极简：「你在曼谷第 3 天，一切顺利」+ 一个「需要帮助」入口。
- 优：极简到极致，情绪价值
- 忧：用户打开就是要干事的，空白等于浪费

## 六、待解决的产品问题

| # | 问题 | 影响 |
|---|---|---|
| 1 | **首页核心是输入优先还是输出优先？** | 输入优先 = 一个输入框（像搜索引擎）；输出优先 = 一张示例卡片（像 Shazam 识别结果） |
| 2 | **要不要预置场景入口？** | 「打车/点菜/买药/问路」这类高频场景的快捷入口能消灭冷启动，但增加首页复杂度 |
| 3 | **成卡后是跳页还是 Sheet 覆盖？** | Sheet = 用户始终在首页，心智模型简单；跳页 = 更沉浸 |
| 4 | **要不要帮用户「听懂」当地人说什么？** | 单向（用户→当地人）vs 双向对讲，产品形态完全不同 |
| 5 | **离线能力有多重要？** | 无网时 App 白屏 = 最危险的时候最没用 |
| 6 | **递卡给当地人看 vs TTS 语音播放，哪个是主路径？** | 有些用户觉得掏手机给别人看很尴尬 |
| 7 | **底部 Tab 要不要保留？** | v2.1 已删除 TabBar（SCN-19），但新设计需重新决策 |
| 8 | **Onboarding 用引导态还是独立流程？** | 内联教学 vs 弹窗 vs 首次使用直接走真实流程 |
| 9 | **首页随旅行阶段动态调整吗？** | 第 1 天需要打车问路，第 5 天可能需要退税找医院 |
| 10 | **旅行结束后的价值是什么？** | 用户回国后会不会再打开？决定产品生命周期 |

## 七、v2.1 的经验教训

### 做对了什么
- **三入口并存**（语音/拍照/打字）覆盖不同场景
- **位置上下文前置**，用户一眼知道语言对
- **安全 FAB 常驻**，紧急场景一触即达
- **简化做减法**（SCN-19 砍掉 3 屏 + TabBar）比加功能更有效

### 可以挑战的假设
- 首页是空白等待态 → 新用户没有心智模型
- HoldMic 大按钮是核心交互 → 有些场景打字或拍照更快
- 对话式布局（02 屏双气泡）→ 核心需求是单向表达，不是聊天
- 需要 11 个屏 → 也许 5 个就够

## 八、下一步

1. **确定产品隐喻**：SceneGo 对用户来说到底是什么——工具/助手/保险/翻译员？
2. **确定首页形态**：从第五节的六个方向中选择或混合
3. **设计 → 画布**：基于方向做新的 Pencil 设计稿
4. **实现**：基于画布重建 UI（当前 App 为空壳，功能内核已就绪）
